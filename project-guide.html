1. What Is This Project?

The Student Learning Dashboard is a web application that helps a student (you!) track their learning progress. It shows all your enrolled courses, how much of each course you have completed, your study activity, a weekly schedule, and your profile.

One-line summary for interviews:
"I built a full-stack student dashboard using Next.js and Supabase that lets users track course progress, view activity logs, manage schedules, and see project portfolios — deployed live on Vercel."

2. Tech Stack — What Every Tool Does

Next.js 16 (App Router) The main framework. Handles routing (pages), server-side rendering, and the overall structure of the app. Think of it as the skeleton.
React 19 The JavaScript library used to build UI components (buttons, cards, grids). Next.js is built on top of React.
TypeScript A stricter version of JavaScript that catches errors before the app runs. Defines shapes of data like what a "Course" object looks like.
Tailwind CSS v4 A CSS utility framework used for all styling — colours, spacing, responsive layout. No separate CSS files needed.
Supabase The backend database (PostgreSQL). Stores all course data. Acts like a Google Sheet in the cloud that the app reads from.
Framer Motion Animation library. Used for the bento grid entrance animations, progress bar fills, and hover effects on course cards.
Lucide React Icon library — provides icons used in the sidebar (dashboard, book, chart, calendar, settings icons).
Vercel The hosting platform. Deploys the app to the internet automatically whenever changes are pushed. It also manages environment variables securely.

Simple Analogy

Think of it like building a house:
Next.js = the blueprint and structure  |  React = the rooms and furniture  |  Tailwind = the paint and decoration  |  Supabase = the storage room  |  Vercel = the address (makes it accessible online)

3. Architecture — How the App Is Structured

Frontend (What the User Sees)

  • Built with Next.js App Router — each folder inside app/ becomes a URL page
  • Components (reusable UI pieces) live in the components/ folder
  • The Sidebar is a persistent layout component that wraps all pages
  • Pages are server components by default — they fetch data on the server before sending HTML to the browser

Backend (Where Data Lives)

  • Supabase hosts a PostgreSQL database
  • The courses table stores all course records
  • The app connects to Supabase using the official @supabase/supabase-js client library
  • Row Level Security (RLS) controls who can read/write data

Deployment

  • Code runs locally during development with npm run dev
  • Deployed to Vercel with vercel --prod command
  • Sensitive keys (Supabase URL and API key) are stored as Environment Variables in Vercel — never hardcoded in code

4. Data Flow — Step by Step

This is how data travels from the database to what you see on screen:

1
User opens the website The browser sends a request to Vercel's servers for the Dashboard page.
2
Next.js Server Component runs The page.tsx file on the server executes. It calls Supabase using the secret API key.
3
Supabase returns course data The database sends back a list of courses as JSON: [{ title: "React", progress: 65 }, ...]
4
Next.js builds the HTML The server renders the BentoGrid component with the real course data injected into it.
5
Browser receives ready-made HTML The page loads instantly with data already in it. No loading spinner for the main content.
6
Framer Motion animates the cards Once the page is on screen, React and Framer Motion add animations — cards fade in, progress bars fill up.
Key concept — Server vs Client components:
Server components (default) fetch data and render HTML on the server — fast and secure.
Client components (marked with "use client") run in the browser — needed for animations, hover effects, and interactivity like the sidebar toggle.

5. Database — Supabase / PostgreSQL

The courses table

ColumnTypeWhat It Stores
idUUIDUnique identifier for each course (auto-generated)
titleTextCourse name e.g. "React Fundamentals"
progressIntegerCompletion percentage (0–100)
icon_nameTextIcon key e.g. "code", "brain" — mapped to a Lucide icon
created_atTimestampWhen the course was added

Row Level Security (RLS)

Supabase has a security feature called RLS that blocks all database access by default. A policy was created to allow public (anonymous) users to read the courses table. This means anyone can view courses but no one can delete or modify them from the frontend.

7. Key Features to Highlight

Bento Grid Layout

The dashboard uses a CSS Grid with unequal column sizes (2fr 1fr 1fr) creating a magazine-style layout called a "bento grid". It's fully responsive — stacks into a single column on mobile.

Server-Side Rendering (SSR)

Data is fetched on the server before the page is sent to the user. This means no flickering or loading spinners for content — the page arrives ready with real data. revalidate = 0 ensures data is always fresh.

Suspense + Skeleton Loading

While the server fetches data, React's Suspense component shows a skeleton placeholder (grey animated boxes). This gives instant visual feedback while data loads.

Error Boundary

If the database fetch fails, the error.tsx file catches the error and shows a friendly "Something went wrong" screen with a "Try Again" button — instead of crashing the whole app.

Framer Motion Animations

The course cards animate in one by one (staggerChildren: 0.1 delay), fading up from below. Progress bars count up from 0% to the real value with an easing animation.

Responsive Sidebar

On desktop: a collapsible icon sidebar on the left. On mobile: a bottom navigation bar (like a phone app). Uses Tailwind responsive prefixes like md:hidden to switch between the two.

8. Common Interview Questions & Answers

Q: What is Next.js and why did you use it?
A: Next.js is a framework built on top of React that adds server-side rendering, file-based routing, and optimizations out of the box. I used it because it lets me fetch data on the server (making the app faster), and each file inside the app/ folder automatically becomes a page URL without any extra configuration.
Q: What is Supabase?
A: Supabase is an open-source backend service that provides a PostgreSQL database, authentication, and REST/real-time APIs. I used it to store course data — it was quick to set up and provides a dashboard to manage data without writing backend server code.
Q: What is the difference between server and client components in Next.js?
A: Server components run on the server and can fetch data directly from a database. They produce pure HTML sent to the browser — fast and secure. Client components (marked with "use client") run in the browser and are needed for user interactions like clicks, animations, and state changes. In this project, data-fetching pages are server components while the Sidebar and animations are client components.
Q: What are environment variables and why are they important?
A: Environment variables are configuration values stored outside the code — like passwords or API keys. I stored the Supabase URL and API key as environment variables so they are never visible in the GitHub repository. In production, they're stored securely in Vercel's settings panel.
Q: What is Row Level Security (RLS) in Supabase?
A: RLS is a Supabase security feature that blocks all database access by default. You create "policies" to define who can do what. In this project, I created a policy that allows any anonymous user to read (SELECT) the courses table, but they cannot modify or delete data.
Q: How is the app deployed?
A: The app is deployed on Vercel. I connected the project using the Vercel CLI and run vercel --prod to deploy. Vercel builds the Next.js app, hosts it on a global CDN, and provides a live URL. It also securely stores environment variables used in production.
Q: What is TypeScript and why use it?
A: TypeScript is JavaScript with added type safety. For example, I defined a Course interface that says every course object must have an id, title, progress, icon_name, and created_at. If I accidentally try to use a field that doesn't exist, TypeScript shows an error before the app even runs — catching bugs early.
Q: How does Tailwind CSS work?
A: Tailwind provides hundreds of utility classes like text-white, p-4, rounded-xl, flex that you apply directly in your HTML/JSX. Instead of writing separate CSS files, you style components inline using these class names. Tailwind generates only the CSS you actually use, keeping the file size small.
Q: What challenges did you face?
A: A key challenge was the Supabase API key — the project initially used an outdated key so the database returned "Invalid API key" errors. I debugged this by testing the Supabase REST API directly with curl, identified the wrong key, and replaced it with the correct Legacy anon key from the Supabase dashboard. I also had to configure Row Level Security to allow public reads.
